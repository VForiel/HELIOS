# WavefrontArray Bracewell Nuller + Camera Support

Date: 2025-12-03

## Summary of Changes
- Adapted the notebook `tests.ipynb` Bracewell nuller cell to support `WavefrontArray` by applying a π phase shift to the second channel.
- Exposed `WavefrontArray` at the package level (`src/helios/__init__.py`) for easier notebook type checks.
- Updated `Camera` to accept `WavefrontArray` and coherently combine channels using baseline `locations`, then FFT to focal plane intensity.
- Validated the detection cell; image renders successfully (with expected log-scale warning due to low values).

## Files Modified
- `src/helios/components/detectors.py`
  - Import `WavefrontArray`.
  - Add `_combine_wavefronts` method (coherent combination + FFT).
  - Update `get_raw_image` to handle `WavefrontArray`.
- `src/helios/__init__.py`
  - Export `WavefrontArray`.
- `tests.ipynb`
  - Update BracewellPhaseShifter cell to handle `WavefrontArray` and adjust visualization.

## New/Updated Functions
- `Camera._combine_wavefronts(wf_array: WavefrontArray) -> np.ndarray`
  - Coherent sum of shifted pupil plane fields based on `locations`, FFT to focal plane intensity.

## Tests & Validation
- Executed notebook cells:
  - Nuller cell (`#VSC-b304dfe9`) now succeeds and plots both channels (amp/phase), showing π shift on channel 2.
  - Detection cell (`#VSC-ab124527`) executes successfully; focal plane image produced. Log-scale warning is benign.

## Notes
- `locations` are used as pixel shifts via `pixel_scale`; current implementation assumes a reasonable pixel scale placeholder in `Wavefront`. Future refinement should set physical `pixel_scale` consistently from upstream optics for accurate baseline-to-pixel mapping.
- If `locations` are absent, channels are summed co-located.

## Breaking Changes
- None; backward compatibility preserved. `Camera` still accepts single `Wavefront`.
