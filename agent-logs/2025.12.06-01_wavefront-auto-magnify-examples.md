# Session Log — Wavefront Refactor, auto_magnify, Examples Save Mode

Date: 2025-12-06

## Summary of Changes
- Refactored `Wavefront` initialization to support new API:
  - Parameters: `wavelength`, `size` (Quantity), `npix`, `nsource`, `value`.
  - Backward compatibility: if `size` is an `int`, it is treated as `npix` (deprecation warning emitted).
  - Ensures `pixel_scale` and `size` remain `astropy.Quantity`-based.
- Added `auto_magnify` behavior to elements with physical sizes:
  - `Pupil.process(wavefront, auto_magnify=None)`: resize or crop wavefront based on pupil diameter; warn when sizes mismatch.
  - `Collector.process(wavefront, context, auto_magnify=None)`: same behavior based on collector `size`.
- Context input wavefront generation updated:
  - `Context.get_input_wavefront(...)` now accepts `size: Quantity` and `npix: int` distinctly.
  - Backward compatibility maintained when `size` is provided as `int`.
- Example scripts updated to support non-interactive save mode:
  - `examples/run_all_demos.py` accepts `--save` and sets `HELIOS_SAVE_PLOTS=true`.
  - All example scripts `01`–`11` save plots to `generated/examples/*.png` when `HELIOS_SAVE_PLOTS` is set.
  - Updated examples to use `npix=N` where appropriate for new `Wavefront` API.

## Notes & Migration
- Examples and user code should prefer `Wavefront(..., size=physical_quantity, npix=int)`.
- Passing `size` as `int` now works but is deprecated; users should migrate to explicit `npix`.
- Elements without intrinsic physical `size` (e.g., `BeamSplitter`, `Lens`, `Coronagraph.process`) do not implement `auto_magnify` as they operate without a physical aperture parameter; if desired, physical mask parameters can be added in future to enable `auto_magnify`.
